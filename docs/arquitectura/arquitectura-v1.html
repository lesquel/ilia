ILIA — Arquitectura lógica y física V1

Plataforma para docentes: cliente web (Expo Web) y app móvil, API en FastAPI, PostgreSQL 17 y almacenamiento de archivos compatible con S3. Despliegue en 5 laptops de la red del laboratorio.

Configuración del balanceador (Laptop 1)

upstream ilia_api {
    server 192.168.1.12:8001 max_fails=3 fail_timeout=10s;
    server 192.168.1.12:8002 max_fails=3 fail_timeout=10s;
}

server {
    listen 80;

    location /api/ {
        proxy_pass http://ilia_api/;
        proxy_next_upstream error timeout http_502 http_503;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-For $remote_addr;
    }

    location / {
        proxy_pass http://192.168.1.11:8080;
    }
}

Límites conocidos de la V1
  • La Laptop 1 es un punto único de falla: si se apaga, nadie entra.
  • La cola de evaluación y el límite de peticiones viven en la memoria de cada contenedor. Con dos réplicas cada una cuenta por separado; para escalar en serio hace falta un almacén compartido (por ejemplo Redis).
  • El backend marca las cookies como Secure por defecto. Sobre HTTP simple el navegador no las guarda, así que en el laboratorio hay que desactivarlo o poner TLS en el balanceador.
  • Las migraciones (alembic upgrade head) se ejecutan una sola vez desde la Laptop 3 antes de levantar los dos contenedores.
